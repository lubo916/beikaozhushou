## 一句话
工程骨架搭好了：10 个检查命令齐全，`pnpm gen` 接管全部生成物并移出 git，18 个领域分成 core 和 server 两层，分层规则和 V3 一致性检查都做成了检查；但沙箱一直断网，代码检查、类型检查、测试、构建、冒烟都没能真跑，所以这轮记“部分完成”。

## 怎么看效果
本地运行 `python3 tools/bk.py run` 后：
- 打开 http://localhost:5173：浏览器标签页标题是“备考助手”；页面上方一行“备考助手”，大标题“学员端”，下面一行“页面正在建设中。”
- 打开 http://localhost:3000/health：看到 `{"status":"ok","env":"development"}`。
- 机构端 http://localhost:5174、平台后台 http://localhost:5175 显示各自原来的占位标题。
- 在仓库里运行 `pnpm gen`，会列出更新了哪些生成物；再运行 `pnpm gen:check`，显示“生成物检查：全部与来源一致”。

## 做了什么
1. 根目录补齐 bk 要用的 10 个命令（dev、dev:real、gen、lint、typecheck、test、build、test:db、e2e:smoke、gallery），启动和检查前都会先自动生成；三个界面固定在 5173、5174、5175 端口；Node 版本按你的拍板写 >=22.18，.nvmrc 是 24，.npmrc 不写镜像地址。
2. 新建生成器 `pnpm gen`（packages/codegen）。它接管参数、错误码、权限、事件指标、页面清单、表元数据六类生成物：其中四份和旧文件逐行比对，除第一行文件头外完全一致；错误码和权限两份旧文件按规定没有打开看，用导出的值、行为、类型三重比对确认一致。另外两类是接口代码（Orval）和数据库客户端（Prisma）。这些生成物全部移出 git。
3. 18 个领域都建成了包，分 core（纯规则）和 server 两层；补了 packages/shared 和 packages/ai 的骨架，shared 里词汇、格式、“今天”三个子入口留给 F03 填。三个界面、接口、后台任务都预先接好了全部领域包，后面的任务不用再改依赖清单，免得抢热点文件。锁文件只补登记了新的工作区包，没有改任何第三方库的版本。
4. 分层规则做成了两道检查（ESLint 和依赖方向检查），都带反例测试：
   - 页面组件不许引用领域包，只有假数据层能用领域的 core；
   - core 不许引用服务端库、数据库、node 内置模块，也不许写裸数字；
   - 禁用库清单（moment、axios、redux、MUI 等）原来就有，保留。
5. 接口加了 /health，配了 3 个不起服务的测试；学员端占位页显示“备考助手”；冒烟测试加了 2 条。网页沙箱里只有 Chromium 一个浏览器，冒烟就只跑它；本地和 CI 照旧跑三个浏览器。
6. 数据库与部署：
   - 表结构按地基文档要求，从 contracts/schema/ 搬到 packages/db/prisma/schema/；
   - 本地数据库 deploy/compose.dev.yml：PostgreSQL 17 自制镜像（含 pgvector、zhparser、pg_bigm），加 Redis 7；
   - 沙箱装库脚本改为同时建开发库和测试库，连不上就友好退出；
   - 两个 Docker 镜像构建时会自动生成各自需要的部分；
   - 新增 GitHub 自动验证：每次推送都跑完整验证，带数据库和 Redis，装好三个浏览器。
7. 把 F01 列给 F02 的 V3 一致性检查都落成了检查：
   - 做成测试的：考试名不写进领域代码；代码里读的参数都已登记；表的归属与数据类别对得上；地基文档不超篇幅；生成物与来源一致；
   - 没人用的参数只提示、不报错；
   - 裸数字做成了 ESLint 规则。
8. tech.md 写回了 34 个锁定版本、生成物清单和领域两层的约定；拍板写成了决定卡 D-2026-10-20-F02-r1。

## 已知未修问题与失败线索

1. **数据不足正文存在嵌套段落。** `index.tsx` 把一个含 `<p>` 的片段传给公共 PageState 的 body，而 PageState 内部本来就用 `<p>` 包 body。可能触发 React DOM 嵌套错误，七态浏览器测试应抓住它。应改成本页内合法的行内元素或现成属性，不能改公共组件来掩盖。
2. **健康度提示借错参数。** 当前使用 `param("plan.calibrate.weeks")` 插值。该参数实际用于“声明与实测连续相差几周后提议校准”，不是健康度最少观察窗，不能因默认都是两周就混用。最小接续可先使用不含阈值数字的“实测记录还不足，健康度暂按声明时间估算并标注”，把专门观察窗参数登记交整合任务；若找到合法已有参数，应按其真实语义使用。暂停指令到达前计划的修复并未执行。
3. **四考试预算样例汇总不一致。** 当前每份 JSON 的 `scheduled_minutes=586`，七个 `day.minutes` 合计实际上为 `486`，每日日程内的任务分钟数已与该日合计相符。当前 `budget_minutes=660`、`buffer_minutes=74` 也随错误汇总而来。可恢复为预算 `540` / 已排 `486` / 缓冲 `54`，并用保留的样例测试验证一致性；不要在页面中重新计算业务数字。
4. **最终格式化尚未完成。** “返回本周”按钮和离线 fieldset 是最后两处源码修改；e2e 也在最后一次格式检查失败后有过完善，须定向格式化、lint 和类型检查。
5. **所有浏览器断言尚待证实。** 特别是三档两/四/七列、窄屏按钮宽度、所有视图独有内容、modal 中“即将上线”的提示可见性、七态的控制台错误，以及 DS 地图体检不通过时锁预测但学习可用。
6. 轮次总结目前是示例统计，未来轮次的统计已在界面隐藏；仍需核对活跃轮次统计与“结束后总结”的产品文案，不能误称真实完成。

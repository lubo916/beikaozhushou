# ADR-020 敏感操作按风险分档

- 状态：已采纳

## 背景

后台与机构端的导出、封禁、改成绩、改权益等操作需要防误操作与防滥用；若一律双人复核，客服日常处理会被堵住（P19-08）。

## 决定

1. 敏感操作分三档：不可逆的（永久封禁、物理删除、大额退款等）经二级审批，双人复核只用于这一档，涉及金额的须手动输入金额或套餐名；可回滚的保存前后快照，可一键回滚；只读敏感的（查看明细、导出）只留痕。
2. 执行任何一档前都重新验证身份；验证服务不可用时一律拒绝，不跳过。
3. 全部写审计日志，可按对象回溯（INV-14）。
4. 机构端使用同一套分档，机构在平台基线上只能收紧、不能放宽。

## 后果

- 高风险操作有双人把关，日常操作不被拖慢。
- 每个敏感操作都要先归档位，写在对应功能规格里。
- 何时重新考虑：审计日志显示某类操作频繁误用时，提升其档位。

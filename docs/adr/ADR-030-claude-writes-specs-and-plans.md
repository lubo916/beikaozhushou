# ADR-030 规格与计划由网页版 Claude 编写，Codex 复核

- 状态：已采纳

## 背景

ADR-024 让 Codex 写规格、做计划，网页版 Claude 实现并做规格冷启动复核。闭环 0.1 的实践表明：Codex 起草的规格经网页版 Claude 多轮复核后，问题越改越多，规格外溢成配套文档，实现细节挤进了规格；同一批规格由网页版 Claude 按依据重写后，一次通过全部机检。产品负责人决定把规格与计划的编写交给网页版 Claude，Codex 专做出包、机检、复核与汇报。网页版 Claude 看不到仓库，它写出的东西只能和交接包里的依据一样完整，所以包的内容必须机械地规定下来。

## 决定

1. 分工：网页版 Claude 编写每个闭环的规格批次（含闭环级任务的计划）与每个功能的实现计划，并按确认的计划实现。Codex 按 docs/meta/plan/packages.yaml 出编写包，回收结果并写入仓库，运行机检，用 review-spec 复核规格、用 review-plan 复核计划，复核通过后用大白话把概况讲给产品负责人；Codex 不起草规格与计划。本条取代 ADR-024 决定 2 中“Codex 写规格、做计划”与“网页版 Claude 做规格冷启动复核”的分工；ADR-024 其余决定不变。
2. Codex 的修改边界：check 报错已给出明确改法的机械问题（漏列 refs、格式、生成物过期）可以直接修正，并记入复核记录；改变任何规则、验收、契约或计划含义的意见，一律写成复核意见退回网页版 Claude，在同一个对话里修改。
3. 异构复核：网页版 Claude 写的规格与计划由 Codex 复核，写的代码由 Codex 复查。重型通道的规格另由网页版 Claude 新开对话、只看任务包做一次冷启动复核，问题与 Codex 的取并集。本条细化 ADR-007 决定 5 的工具组合。
4. 交接包的内容以 docs/meta/plan/packages.yaml 为唯一来源，按 doc-system“最小而充分”的原则由登记机械推导：功能的领域与依赖、覆盖条目、规格的 refs、闭环的切片与任务。任务包里已有的切片不再附原文，大文件只摘需要的章节。scripts/handoff.py 缺少不可选的来源就拒绝出包，并在包内 context/SOURCES.md 列出全部文件、读法与理由。网页版 Claude 在结果中点名需要补充的文件，下一轮自动补上；反复点名的补进 packages.yaml。
5. 冻结原型不常规附带：网页版 Claude 写明页面登记、切片与截图缺信息、需要原型时，下一轮规格编写包附上。这是 doc-system 4.1 的又一个 L4 例外；与登记冲突时以登记为准，原型的变量名与样式数值不写进仓库。
6. 写入范围：规格编写结果只能写本闭环功能的规格、contracts/、docs/product/glossary.yaml 与 docs/meta/plan/work/；docs/models/ 可以写，但 Codex 必须在大白话概况里列给产品负责人确认。路线图、分期、闭环文件与总步骤表的调整写成提议，负责人确认后由 Codex 落地；新的 ADR、跨功能待定问题与约定变更由 Codex 在主干编号后落地。计划编写结果只有 PLAN.md，由 handoff.py 写进 work 文件的“计划”一节。
7. 时机：功能计划在该功能开工时（P2）按当时的仓库状态确定。没有预写稿的，网页版 Claude 按计划编写包写；已有网页版 Claude 预写稿的，Codex 用 `handoff.py adopt-plan` 换入并复核，不符合现状时退回网页版 Claude 修改。实现回到写计划的同一个对话，没有这样的对话时新开。闭环级任务的计划随规格批次编写，写明主干上可机检的定位判据，由 Codex 执行。
8. 对话与文件：产品负责人在对话里只粘贴 handoff.py 给出的一句话，不另加要求，要求一律经 Codex 写进下一轮的包。结果包逐字按 TASK.md 命名，下载到浏览器默认的“下载”文件夹或 ../handoff/inbox，由 `handoff.py in` 查找。Claude 项目里只粘贴项目说明，不上传任何文件。

## 后果

- 产品负责人每个闭环多搬运一组编写包，每个功能多搬运一组计划包；确认时看的是 Codex 复核过的大白话概况，不再读原始规格。
- 规格与计划的质量取决于编写包是否完整，这由 packages.yaml、handoff.py 的拒绝出包与 selftest 机械保证；网页版 Claude 反复缺的依据补进 packages.yaml。
- 装有 Claude Code 时，它可以代替网页版 Claude 在仓库里直接编写与实现，复核仍由 Codex 完成。
- 何时重新考虑：Codex 的复核长期没有发现阻断问题，或网页版 Claude 的编写轮次明显多于 Codex 起草时。

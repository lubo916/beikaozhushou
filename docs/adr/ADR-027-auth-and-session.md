# ADR-027 登录与会话

- 状态：已采纳

## 背景

换鉴权等于全站返工。原型要求手机验证码、密码、游客先体验后合并（S01、ADR-012）、员工账号双重验证（O15、P19）；微信生态下还要把同一个人在服务号、网站与将来的 App 里认成一个人。

## 决定

1. 用 Better Auth，会话存数据库，随时可作废；浏览器只持 HttpOnly Cookie，不在浏览器存储令牌。
2. 学员：手机验证码、密码、游客匿名会话，登录后按 ADR-012 合并数据；微信登录写独立适配。员工：单独的会话与 Cookie，强制双重验证，单会话。
3. 微信服务号网页授权、开放平台网站应用与将来的移动应用绑定同一个开放平台账号，以 UnionID 识别同一个人；写第一行登录代码之前完成绑定。
4. 1.6 的 ACCT-01 写规格之前，用最小样例验证手机号登录、机构插件、双重验证与微信适配四项；任一项不通过，按重型通道另选方案并修改本 ADR。
5. 接口默认要求登录，公开接口在 contracts/openapi.yaml 中显式标注；发短信前先过验证码，并按参数限流。

## 后果

- 微信与 Apple 登录仍在 4.1 扩展（ADR-022）；App 阶段改用令牌登录（ADR-029），只增加令牌签发，会话模型不变。
- 何时重新考虑：最小样例验证失败，或 Better Auth 停止维护。

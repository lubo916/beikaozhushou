# ADR-029 多端与触达路线

- 状态：已采纳

## 背景

ADR-022 定了响应式网页先行。技术选型定稿补充了 App 套壳、小程序、推送与浏览器下限的路线，并指出安卓网页推送在国内基本收不到，iOS 要把网页加到主屏幕才能推送。

## 决定

1. 现在做响应式网页与 PWA：vite-plugin-pwa、idb 与统一的待提交队列加幂等键，在行走骨架在线跑通之后再加离线；微信内置浏览器当一等公民。断点照原型：外壳容器宽度小于 700 为手机（抽屉与底部五个入口，导师为底部面板），700 至 1023 为平板（图标栏），1024 起为桌面（侧栏）；局部用 860 与 1180；取值在 design/tokens.json 的 size.breakpoint，用容器查询实现。浏览器下限 Safari 16.4、Chrome 111、Firefox 128，低于下限显示“浏览器版本过旧”提示页。
2. App：上架时用 Capacitor 把同一套前端套壳，补原生推送、相机与录音，App 端改用令牌登录、接苹果内购并办理 App 备案；手感不够的个别页面再用 Expo 重写。时点在 4 期上线门槛之前评估（ADR-022），通过后作为闭环排入当期或 8+ 主题池。
3. 小程序：先用 web-view 内嵌网页，需要企业主体与业务域名配置。
4. 触达：站内通知中心、短信（只发关键提醒）与微信服务号消息；平台统一频控与深夜静默（INV-23）；不依赖安卓网页推送；厂商推送随 App 接入。
5. 同一场练习与模考用 Redis 租约做多端互斥；模考计时以服务器时间为准。
6. 本 ADR 细化 ADR-022 决定 2 中小程序与原生应用的路线，取代 ADR-022 决定 3；ADR-022 其余决定不变。

## 后果

- 学员端截图宽度为 375、834、1280（scripts/spec_tool.toml 的 shots）；834 的截图在装好 Playwright 后运行 shots 补齐。
- 真机清单：iPhone Safari、安卓 Chrome、微信内置浏览器（iOS 与安卓各一台）、华为或小米自带浏览器、iPad 横竖屏、电脑 Chrome 与 Edge；闭环收尾走查按此抽查。
- 何时重新考虑：受众强依赖微信生态时，评估小程序先行。

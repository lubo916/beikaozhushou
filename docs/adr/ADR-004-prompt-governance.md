# ADR-004 提示词治理

- 状态：已采纳

## 背景

后台有提示词模板、示例库与灰度管理。若后台可以直接编辑并发布提示词，线上行为就会脱离代码评审与评测，出了问题无法回溯到版本。

## 决定

1. 提示词与输出结构以仓库 packages/ai/<场景>/ 为唯一来源，随代码版本走；场景登记在 contracts/ai/scenarios.yaml，评测在 evals/<场景>/。
2. 后台只能在仓库中存在、且该版本回归评测达到阈值的提示词之间灰度与回滚，不能编辑正文。
3. 改提示词必须跑对应场景的评测，不低于基线（AGENTS.md 红线 7）；任一关键指标低于阈值即阻断发布（INV-17）。
4. 灰度以学习效果指标判定，不以点击率判定（INV-16）。
5. 后台确认的纠错与好评回答，经人工挑选后以提交的形式回流到评测用例或示例库。

## 后果

- 每个线上行为都对应一个可评测的版本。
- 运营不能热修提示词，紧急情况用场景的降级开关。
- 何时重新考虑：评测覆盖稳定后，可允许后台调整少量登记过的变量（仍按参数登记）。

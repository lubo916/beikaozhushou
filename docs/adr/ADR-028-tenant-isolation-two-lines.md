# ADR-028 租户隔离的两道防线

- 状态：已采纳

## 背景

ADR-011 要求从一开始就对全部业务表启用数据库行级安全。技术选型定稿认为早期全表开启会拖慢开发与测试，改为应用层与数据库两道防线，行级安全在接入第一家真实机构之前上线。机构之间的数据泄露仍是最重的红线。

## 决定

1. 第一道：所有读写经过带“当前用户、当前机构”的数据访问层（packages/db 的唯一构造处），每条可见性规则配一个越权测试。
2. 第二道：接入第一家真实机构之前（7.1 收尾之前），给机构相关表开启数据库行级安全，应用连接使用无绕过权限的角色；测试与预发环境同样开启。
3. 本 ADR 取代 ADR-011 决定 2、3；ADR-011 决定 1（每张业务表都有 tenant_id）与决定 4（平台人员访问机构数据须审批并留痕）不变。

## 后果

- 0 期起表结构就带 tenant_id，开启行级安全时不改表结构。
- 7.1 收尾时核对：越权测试全部拦住，行级安全已在测试与预发环境开启。
- 何时重新考虑：单个机构需要独立部署时，评估按租户分库。

# 文档写作约定

## 规则
1. 只写现状，不写“原来、改为、之前”；取舍理由写进 ADR。
2. 先写结论，再写条件与例外；一句话只讲一件事。
3. 要求写成可判定的句子；能机检的规则移入检查，并在行尾注明检查编号。
4. 默认值写参数名，不写数字。
5. 每条规则附一句理由；不用全大写强调，不堆叠“必须”。
6. 用肯定式写要达到的结果；写禁令时同时给出替代做法。
7. 同一件事只写一处，别处引用编号或路径。
8. 清单类事实用 YAML 登记，不用 Markdown 表格作源。
9. 术语以 docs/product/glossary.yaml 为准，新术语先登记。
10. 编号（功能、ADR、不变量、跨功能待定问题）只在主干用 new 命令分配。
11. AGENTS.md、约定与 skill 中只写要达到的结果，不写某个工具专属的命令或模式名称。

## 示例
- 正例：“回炉间隔取参数 practice.mistake.review_intervals；没有可用变式时，毕业所需的做对次数增加 practice.mistake.no_variant_extra_count 次。”
- 反例：“回炉间隔原来是 1、3、7 天，后来改为 1、2、4 天。”：带历史、写数字，读者分不清现在是什么。

## 理由
AI 会把读到的每一句都当成现行规则；历史、重复和模糊的措辞会被当真。写作规则统一，文档才能被机械检查，也才能被两个工具同样理解。

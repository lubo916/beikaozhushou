# 测试约定

## 规则
1. AC 测试的标题含 [<功能ID>-AC<n>]，不变量测试含 [INV-<nn>]，黄金路径端到端测试含 [GP-<n>]。
2. 测试不依赖真实时间与随机数：时间经可注入的时钟，随机经固定种子。
3. 测试数据取自 fixtures/exams/ 的演示考试；领域测试至少覆盖主种子与对照考试两门。
4. 涉及 AI 的单元测试用返回固定输出的替身模型；模型质量只在 evals/ 中按阈值评测。
5. 修缺陷先补能复现它的测试，再改代码。

## 示例
- 正例：`it("周一做错的题周四进入巩固段 [PRAC-05-AC2]")`，时钟注入为 2026-10-12，再拨到 10-15 断言出现在到期队列。
- 反例：`expect(explain(q)).toContain("公允价值")` 直接断言模型输出：模型一换就失败，也测不出讲解质量。

## 理由
功能完成状态由“每条 AC 都有通过的测试”推导（doc-system 8.6）；标题标签是连接规格与测试的唯一纽带。两门考试同测，才能发现按考试写分支的代码。

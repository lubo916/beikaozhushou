# 默认收尾流程优化
- 日期：2026-10-24；来源：用户明确要求落实多任务综合评审，包含 tools/ 与 AGENTS.md。
- 背景：多任务历史显示前段失败后长跑、环境/产物异常、排队与重复取证可造成额外收尾时间。
- 决定：启用默认阶段 failfast、独立运行身份与证据、环境前检、统一串行队列/锁、候选一致性、制品与远端核验；细则见 docs/engineering/acceptance-flow.md。
- 人工：沿用现有交接单，关键业务/跨页证据、同源问题一次扫描、已有截图复用、等待只核变化、共享能力前置；机械修正按风险验证。
- 边界：保留现行七项与用户既有 gate、任务范围、红线、B08 前置、第三轮熔断和既有授权范围；不新增每批等待用户门槛。
- 暂不开启：阶段续跑、测试/文档复用、批量放行、选测和正式重检查并发；flaky 或未知失败不因重跑绿自动放行。
- 接续：本地经 bk-v4 权威入口；网页端新包从 repo/ 执行 python3 ../BK_RUNTIME/bk.py，按包外当前协议接续，保留旧任务 Git 来源；旧包和已运行进程不自动升级。

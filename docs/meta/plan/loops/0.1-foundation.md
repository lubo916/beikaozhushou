## 环境、身份与持久化

EXAM_PREP_ENV 是 development/test/staging/production，未设为 development，未知值拒启动。0 期 apps/api、apps/worker 只在前三者启动：production 因未交付正式身份适配器而拒绝启动，任何开发开关都不能绕过。参数库自身可独立加载 production 覆盖文件，和应用禁止启动分别测试；前端 production 构建无演示路由。Vite build 必须显式给 EXAM_PREP_ENV（本地 serve 可默认 development），构建为只含环境名的 __EXAM_PREP_ENV__ 常量，不暴露其余环境变量；production 的演示路由及 fixture import 被移除。静态托管提供 SPA history fallback，非 API 的 HTML 路由返回入口文件；未知 /api 路由仍为公共 404，不重写成 HTML。

fixtures/runtime/phase0.json 是固定演示身份源：identity 为 learner、anonymous_identity 为不同 id 的 guest，同租户，含 IANA 时区及 simulated:true。服务端 EXAM_PREP_DEV_IDENTITY=fixture 显式启用 learner，未设用独立 guest，其他值拒启动。development/test/staging 均用此模拟适配器，不代表真实匿名会话；浏览器的字段、头或路由不能切换身份。

```ts
type Identity = { id: string; tenant_id: string; role: string };
type Actor = { kind:'client'; identity:Identity }
  | { kind:'domain'; caller:'platform'|'practice'|'plan'; identity:Identity };
type Context = { actor:Actor; timezone:string; simulated:true };
```

未知 role 保留原字符串后拒绝，不转成 learner。getParams 仅允许 platform.params.read 动作中列出的十个角色，其他已登记角色也为 403；getRuntimeContext 允许 platform.runtime.read 的 guest/learner。公开 trackEvent 允许 metrics.event.track 的 guest/learner，内部 recordEvent 按 metrics.event.record.callers 及事件 owner/source 验权，内部 identity.role 也限 guest/learner，roles:[] 不用于拒绝受信服务调用。所有记录目标由 Context 派生；额外客户端身份字段是结构错误，不能激活另一个身份。self 查询按 tenant/id 过滤；同 key 的两身份互不干扰。内部接口返回值及错误见 METR 契约。

0.1b 镜像代码根为 /app，本地启动显式传 repoRoot，不由任意 cwd 推断。EXAM_PREP_PARAMS_DIR 未设时取 repoRoot/deploy/params，镜像含四个文件；替换部署文件仅在下次启动生效。PLAT-02 的 paramsDir/readFile 注入供临时目录测试，客户端不能传这些配置。

EXAM_PREP_STATE_DIR 在预发为 /var/lib/exam-prep，compose 的命名卷 exam-prep-state 挂载此处；本地默认 repoRoot/.local-state。EXAM_PREP_METRICS_STORE 未设时为该目录 metrics/events.jsonl，配置绝对路径时须处在挂载状态目录内，启动校验。METR 测试各自临时目录，开发 CLI 允许显式 --store；文件锁、fsync、损坏恢复按 METR 契约。重新建容器/部署后旧事件仍可查；删除卷不属于发布/回滚流程。

发布流程把 release id、提交、环境及覆盖文件 SHA-256 写 deploy/releases/<release-id>.json，不保存值或密钥。这只是 0.1 的技术发布证据；PLAT-03 落地时迁移格式与旧记录，不以此提前验收操作审计功能。

## 公共错误与检查顺序

0.1b 配 Fastify 公共错误映射、not-found 和意外异常处理器，响应统一 {code,message_key,details}；内部 FieldIssue[] 一律包装为 details:{issues:[{field,reason}]}，无字段问题时 issues:[]；details 只给字段路径/错误类别，不返回值、路径、身份、栈或配置内容。HTTP 解析阶段先于领域检查；请求 bodyLimit 读取 api.request.max_body_bytes。

|HTTP|登记码|触发|
|---|---|---|
|400|COMMON_BAD_REQUEST|坏 JSON|
|413|COMMON_PAYLOAD_TOO_LARGE|请求体超过登记上限|
|415|COMMON_UNSUPPORTED_MEDIA_TYPE|有请求体但媒体类型不支持|
|404|COMMON_NOT_FOUND|未知 API 路由|
|500|COMMON_INTERNAL|未预期异常；服务端日志用关联 ID，不回显请求值|
|503|COMMON_UNAVAILABLE|受信上下文不可用、必需实例未装配或已知仓储故障|
|403|COMMON_FORBIDDEN|角色/caller、已知事件来源或 owner 不获准|
|422|COMMON_VALIDATION|合法 JSON 的字段/属性/时间/键不合法，含 guest 属性不匹配|
|409|COMMON_CONFLICT|结构合法后，同幂等命名空间和键的 payload 不同|

领域顺序固定：Context 可用性 → 角色/caller → 已知事件 source/owner → 完整结构/时间/属性/幂等键 → 已提交键冲突 → 持久化。先失败的步骤决定错误；公开 server 事件即使属性有错仍为 403，不获准角色缺键也为 403；属性不合法且已存在不同 payload 的键为 422。未知/非 active 事件为 422。额外身份字段为 422，不写入；没有目标身份参数时不制造“越身份请求”测试。

事件键为 1–128 个可见 ASCII 字符（! 至 ~），不含任何空白，不 trim 后接受；协议常量属于明确协议格式。两入口同规则；命名空间为 tenant/id/source/name/key。时间契约为 RFC 3339 大写 T/Z、有秒、有 Z 或 ±HH:MM、可选 1–3 位小数，另验证日历/时区偏移；拒绝闰秒、未知负零偏移和更高精度，不截断。规范化为 UTC 毫秒，递归排序对象键、保留数组顺序。具体幂等返回与仓储操作按 METR 契约。

## 前端接线与集成验收

0.1b 在 apps/learner/src/bootstrap 中、React 挂载前创建唯一 createClientParams() 实例，Provider 通过实例 subscribe/getStatus 分别作为 useSyncExternalStore 的订阅/快照函数；ui 只接已读数值/Clock，不导入 params。成功 loadSnapshot 通知后，正在 loading 的 slowHintSeconds 按已持续时间重算，不重置页面。

界面 MessageKey 从本地 zh-CN.json 的 keyof typeof 派生（开启 resolveJsonModule），createUi<MessageKey>() 绑定泛型 Provider/组件，ui 不反向导入应用类型；确切签名见组件输入契约。

生成的 getParams 钩子设置 enabled:false、retry:false、staleTime:Infinity、gcTime:Infinity、refetchOnMount:false、refetchOnWindowFocus:false、refetchOnReconnect:false；启动服务显式 refetch 一次，防重复启动。unloaded/failed 使用登记默认；失败后只由显式“重试加载配置”动作再取，进行中防重；effective 后不再取或注入，非法状态调用按 PLAT-02。getRuntimeContext 同样无自动重取，成功摘要在应用本次生命周期内有效；切换服务端开发身份需重新启动前后端。

getRuntimeContext 仅返回由同一 Context 派生的 {guest,simulated:true}，不含身份/租户值。启动/visibilitychange 从 hidden 到 visible 形成一次打开事件；应用初始 visible 不再额外造一个前台事件。适配器订阅 PLAT-01 useShellLocation 的 ready/entry：ready=false 时等待规范化完成，entry=null（演示/404）则不发送；tutor 覆盖层为 tutor，immersive 页取所属登记入口。仅路由切换、重渲染不算打开事件。

每次发生点生成并保存一个 UUIDv7 幂等键及 payload（entry、bootstrap.guest、发生时钟）；trackEvent mutation retry:false，不创建离线队列。失败保留本次 payload/key，开发 retryOccurrence(id) 显式重试同一份；新发生点用新 key。bootstrap 无摘要则不猜 guest，不发送该次事件；网络/参数失败保持外壳可用。本期 onReport 在本地和预发均用可注入结构化桩（只 pageKey/errorCode），不装 GlitchTip SDK；正式接入前另登记 SDK 版本并复核。

# 闭环 0.1 共同工程前置

本文是 PLAT-01、PLAT-02、METR-01 第二轮规格复核的共同上下文，说明 0.1b 的实现责任、生成物与隔离验证方式。三份规格保持 draft；本文列出的工程前置和运行时代码尚未交付，不能据本文认定已实现。行为分别以功能规格、契约、ADR-025 至 ADR-029 为准，本文不建立第二套登记来源。

## 实施顺序与闭环边界

1. 0.1b 建立 ADR-025/026 的工作区、应用/包骨架、依赖方向检查、Vitest/Playwright/Fastify inject、统一错误映射、可注入身份上下文、生成器迁移和下表全部生成产物；完成 CI、预发部署接线及低版本浏览器提示。
2. PLAT-02 在工程前置上实现参数运行时、覆盖文件读取、getParams 路由和隔离测试。
3. PLAT-01 在 PLAT-02 后实现外壳/通用组件、参数访问器注入点和演示。METR-01 在 0.1b 后可独立实现，不依赖真实练习、计划或 learner 账本。
4. 三项到位后，0.1b 的闭环联调任务装配 getParams/app_opened 链路、检查预发更新和外壳访问，并执行各功能 AC。联调不会把未实现的学习功能列为已通过。

切片与验收句取 docs/product/phases.yaml：PLAT-01 承担 0.1c/0.1d，PLAT-02 承担 0.1e，METR-01 承担 0.1f。闭环 0.1 没有已编号黄金路径；“做一题→证据→档位→方格变色”的 GP0 属于后续 0.3，不能要求本闭环提前实现。0.1f 以受信服务端模拟作答落事件验证，业务发出方的提交/揭晓、手动勾选与证据完成判定由所属功能验收，不给模拟替身冒充真实用户端到端。

## 生成物与手写文件的分界

当前 scripts/spec_tool.toml 的 gen.params_out 是 packages/params/index.ts，现有根 gen 生成参数 index 以及 roadmap/progress 等文档产物。下表目标产物不能当作已经存在；0.1b 必须先迁移配置/生成器和漂移检查，再交付功能实现包。

|来源|0.1b 应生成的产物|实现者可手写部分|
|---|---|---|
|contracts/params.yaml|packages/params/registry.generated.ts：完整 PARAMS、description/sourceItems、ParamName/ParamValue|packages/params/runtime.ts、index.ts，按 PLAT-02 实现并从手写 index 导出登记与运行时|
|design/tokens.json、tokens.resolver.json|packages/ui/generated/tokens.css，Terrazzo 编译，主题叠加取 resolver|ui 组件与消费样式；缺失源令牌由 Codex 补齐并复核后出包|
|design/screens/learner/*.yaml|packages/ui/generated/learner-pages.ts，含页面/视图 mode、title 及外壳所需只读登记|apps/learner 路由、组件注入，不另存登记事实副本|
|contracts/openapi.yaml|packages/contract：Orval 类型、Zod 校验、请求钩子与模拟产物|领域路由和 apps/api 装配；浏览器只经生成钩子调用|
|contracts/events.yaml|packages/domains/metrics/generated/events.generated.ts：事件名、owner/source/status、属性类型及 schemaHash|METR-01 的校验、受信入口、JSONL 仓储、查询|
|contracts/metrics.yaml|packages/domains/metrics/generated/metrics.generated.ts：指标登记、formula_ref、目标/最小样本、来源内容哈希|仅开发 fixture 验证/查询，不生成 learner/plan 的生产算法|

生成物带 GENERATED 标记，禁止直接编辑；改登记后通过唯一根 gen 流程更新。0.1b 将 CSS、页面登记、契约生成及两类分析登记快照接入该流程，并更新 E-GEN-01/02 的预期产物集合。registry.generated.ts 迁移后，index.ts 是手写公开入口，不再被 gen 覆盖。

0.1b 同时按 ADR-026 完成表结构 YAML 向 Prisma 多文件 schema 的转换、生成接线与 E-OWN/E-DC 解析迁移；切换前仍以 YAML 为源，切换在同一次提交内完成，不能留下两套可独立修改的表结构来源。三个功能都不新增业务表，不需要借此提前实现证据账本。

events.generated.ts 的 schemaHash 是构建时 contracts/events.yaml 原始文件字节的 SHA-256；metrics.generated.ts 的内容哈希对应 contracts/metrics.yaml。哈希来源独立，不取 Git HEAD、最近提交号或运行时 YAML。事件记录保存其实际验证所用事件 schemaHash；旧记录保留原哈希和属性，不按新登记重解释。生成快照须与构建一同发布，工作区内容变化也会反映为新内容哈希。

## 身份、权限与统一错误

fixtures/runtime/phase0.json 是 0 期开发身份夹具的唯一来源，结构为：

```ts
{
  identity: { id: string, tenant_id: string, role: 'learner' },
  anonymous_identity: { id: string, tenant_id: string, role: 'guest' },
  timezone: 'Asia/Shanghai',
  simulated: true
}
```

两份 identity 的 id 是文件中不同的固定 UUIDv7，tenant_id 为同一个固定 UUIDv7，时区为有效 IANA 名称。具体值只读该文件，不在各功能重复声明；测试可替换 UUID、IANA 时区、guest 或非法角色。上下文通过服务端受信装配注入，客户端不能提交身份、租户、角色、caller 或版本来构造上下文。

```ts
type Identity = { id: string; tenant_id: string; role: string };
type Actor =
  | { kind: 'client'; identity: Identity }
  | { kind: 'domain'; caller: 'platform' | 'practice' | 'plan'; identity: Identity };
type Context = { actor: Actor; timezone: string; simulated: true };
```

Identity.role 在权限检查前保留字符串，便于测试未登记/不获准角色，不将未知角色强转 learner。显式开发注入开关为服务端 EXAM_PREP_DEV_IDENTITY=fixture，默认关闭；其他非空值拒绝启动，EXAM_PREP_ENV=production 时开启也拒绝启动。开关只读服务端部署配置，不接受浏览器参数、请求头或公开路由激活。

显式开发注入取 identity 的 learner；未启用时，公开匿名路径取 anonymous_identity 的独立 guest，不借用 learner id。两者的 self 查询、事件记录和幂等命名空间分别隔离，测试覆盖相同 key 在两身份下互不干扰及查询不串数据。该固定匿名身份仅供 0 期单开发者模拟验证，不代表真实匿名会话；0.1 fixture 身份适配器在 production 禁止装配，关闭 learner 开关也不能绕过。真实匿名会话归后续认证功能，不在本期增加 cookie 或令牌。

getParams/trackEvent 的公开性以契约 x-public: true、security: [] 显式声明，不因公开而跳过权限：getParams 检查 platform.params.read，trackEvent 检查 metrics.event.track 的角色和 self 范围；非法角色、越身份或越租户返回 403。本期不实现正式登录或自签令牌。

0.1b 提供公共错误体 {code,message_key,details} 及以下映射，领域返回登记码，Fastify 统一装配为 HTTP 响应。details 只含字段路径与错误类别，不回显提交值、身份夹具、部署文件内容或原始异常。

|HTTP|登记错误码|条件|
|---|---|---|
|422|COMMON_VALIDATION|请求/登记属性/幂等键格式不合法|
|403|COMMON_FORBIDDEN|角色、范围、来源或受信 caller 不获准|
|409|COMMON_CONFLICT|同幂等命名空间与键携带不同规范化 payload|
|503|COMMON_UNAVAILABLE|仓储不可用、损坏或写入失败，不能宣称已接收|

所有写操作接受非空 Idempotency-Key；内部入口显式接 key。事件按 tenant、identity、source、事件名和 key 隔离，同 payload 重试返回首次结果且不重复写，同键不同 payload 为 409。规范化、仓储落盘和失败测试以 METR-01 为准，权限失败不会写入。

公开 trackEvent 仅接受 source=client 的 app_opened。内部 recordEvent(context,event,key) 要求 domain actor，caller 只在 platform/practice/plan 中按事件 owner/source 验权；当前 server 事件分别由 practice/plan 调用。登记为 client 的事件不能因为平台 caller 受信就绕过来源限制。两种入口共用相同事件类型校验、幂等与仓储；浏览器提交 server 事件或伪造 caller 均拒绝，内部入口不另开公开路由。

## 参数部署、外壳接线与浏览器前置

覆盖文件为 deploy/params/<env>.json，EXAM_PREP_ENV 只允许 development/test/staging/production，未设置取 development。服务端启动一次读取选定文件，不热加载、不回退其他环境。缺失/不可读/非法 JSON/重复键/非对象/未知名/错型均拒绝启动，无覆盖须提交显式空对象；null 按 PLAT-02 表示无覆盖。出现 gray_required 键（包括 null）即拒绝。错误不能被浏览器默认参数掩盖。

0.1b 发布流程在 deploy/releases/<release-id>.json 写发布标识、提交标识、所选环境及覆盖文件内容 SHA-256 摘要，不写覆盖值或密钥。PLAT-02 只实现读取和规则，发布记录归工程流程，不引入参数管理界面。

0.1b 闭环联调在 apps/learner 启动时通过生成 getParams 钩子加载全量快照，交 PLAT-02 loadSnapshot 后才标记 effective（ready）。unloaded/failed 只用登记默认值，标明来源状态；失败/坏响应不阻塞外壳，也不宣称已取到服务端值。重试与有效快照的生命周期遵循 PLAT-02，不在组件里另建一套默认值。PLAT-01 组件仅从外壳接受读取结果，ui 不依赖 params。

0.1b 实现技术启动接口 getRuntimeContext（GET /api/runtime-context），按 platform.runtime.read 检查，仅由服务端当前 Context 返回 {guest:boolean,simulated:true}，不含身份/租户/角色值；请求不得用于激活身份。前端通过生成钩子读取此摘要，不自行读静态 learner 夹具推断角色；接口不可用时不猜 guest、不发送该次启动事件，保留外壳可用。测试覆盖默认 guest、显式开发 learner、非法角色拒绝及摘要不泄露身份。

联调适配器在启动/回到前台时通过 trackEvent 上报 app_opened：entry 取 PLAT-01 当前入口键，guest 取同次服务端启动摘要，occurred_at 取可注入时钟，幂等键以一次发生点为单位生成并在重试复用。组件重渲染不新建发生点；网络失败保持外壳可用。服务器事件与真实业务页面接线在后续 owner 功能落地，0.1f 只测受信模拟调用。

低于 ADR-029 登记浏览器版本时的提示页归 0.1b，在挂载依赖相应能力的外壳前判断并展示。PLAT-01 的截图、焦点和主题验收使用支持版本；0.1b 另验证提示页，不能让外壳功能包自行猜支持策略。

## 隔离测试与工具维护责任

工具检查和生成器由 Codex 维护；功能实现者不改 scripts/** 或 GENERATED 文件。需要测试工具行为时，只在 tests/** 新增测试并调用真实脚本，对临时根目录运行，禁止修改工作仓库再还原来测试漂移。

测试用 Python sys.executable 启动 scripts/spec_tool.py，命令参数顺序为：

```python
[sys.executable, str(tool), '--root', str(temp_root), 'gen']
[sys.executable, str(tool), '--root', str(temp_root), 'check']
```

tool 是真实仓库脚本的绝对路径，temp_root 是每例独立临时目录。按用例复制必要的最小配置、参数/契约/路线图/页面等登记及期望产物，所有修改和生成输出只落临时根。正例先生成并确认通过，再有针对性修改源/产物测试 E-GEN-01/02；负例检查退出码及对应检查编号，不能用缺少无关必需文件造成的错误冒充目标失败。0.1b 同步维护最小测试根构造方式，保证检查仍使用生产实现。

E-PARAM-01 拦截未登记参数引用；E-PARAM-03 的数值白名单只有 0、1、-1。TypeScript 同行可写 // param-exempt: <具体理由>，仅豁免明确的单位换算或 HTTP 协议常量，不能隐藏业务阈值。测试/演示固定时间属于显式夹具，用途与引用路径要清楚；不复制到生产领域计算。灰度/可调阈值仍只走参数登记。注释理由需人工复查，工具只识别显式语法。

主种子和对照考试测试不豁免。复核包包含 fixtures/exams/junior-accounting 与 fixtures/exams/cet-6 的 profile.json、knowledge-map.json、questions.json；领域用例用相同代码逐门传入，确认无按考试分支。与考试无关的参数/事件逻辑也可复用同一断言和输入形状，不要求发明考试差异，但不能省去对照考试。

METR-01 的证据/片段/计划输入只来自其隔离 fixtures，不把分析事件变成 learner 已接受证据；待验证作答不据此入账。分钟边界、计划分母等未登记生产约定继续按规格 OQ 返回 not_ready，真实 learner/plan 接入时复核并替换 fixture 适配层。CSV 和开发 CLI 仅供模拟验证，不替代 apps/worker 的正式业务导出。

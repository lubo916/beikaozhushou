### 4.3-1 BILL-01 档位、额度与核心闭环不设限

`billing` · R3 · 依赖 ACCT-01 · 规格：未写 · 涉及跨闭环依赖

覆盖条目（6）：S31-01 三档对比（P0） · S31-02 核心闭环不设限（P0） · S31-05 限的是规模与高成本能力（P0） · S31-06 用量与额度（P0） · S31-07 到期降级不阻断（P0） · S31-12 设备上限随档位（P1）

规格种子（来自分期规划切片 4.3a、4.3d；写规格时转成 R 与 AC；与契约、ADR、glossary 冲突时以后者为准）：
- **4.3a 三档与额度模型，“核心闭环不设限”写成测试**（建议切片）　与 BILL-04 共用切片
  - 范围：先把规则写成测试表（每一行“输入→期望”是一条单元测试），我核对后再实现到全绿
  - 验收：自动化测试证明：任何档位下今日清单、计划、到期复习、错题回炉都不限量；限的只是规模与高成本能力；额度改动先灰度。
  - 提醒：硬约束先写成自动化测试，以后每次改额度都跑（第 8 章 S31 的切法）。
- **4.3d 用量与额度、到期降级不阻断**（建议切片）　与 BILL-03 共用切片
  - 验收：各项能力已用与剩余可查；到期后数据全部可见可导出、核心闭环照常，超出免费规模的部分转只读；到期前分档提醒。

人工把关：真机看：手机 375 与桌面 1280 按验收各走一遍（并入闭环收尾走查）；规则表逐行核对：业务确认时看决策表与原型说法是否一致（本功能最重要的把关）

### 4.3-2 BILL-02 购买、支付、订单、发票与退款

`billing` · R3 · 依赖 BILL-01 · 规格：未写

覆盖条目（6）：S31-03 两种购买方式（P0） · S31-25 支付渠道（P0） · S31-08 订单记录（P0） · S31-17 支付失败处理（P0） · S31-15 发票申请（P0） · S31-16 退款试算、申请与进度（P0）

规格种子（来自分期规划切片 4.3b、4.3c、4.3e；写规格时转成 R 与 AC；与契约、ADR、glossary 冲突时以后者为准）：
- **4.3b 单次购买与一种支付渠道**（建议切片）
  - 验收：用一种渠道买到考期通行证；订单与状态可查；续费与退款回到原购买渠道办理。
  - 提醒：先只接一种支付渠道、只开单次购买；自动续费放在本闭环最后几个切片（4.3 原文）。
- **4.3c 支付失败处理与权益开通**（建议切片）　与 BILL-04 共用切片
  - 验收：按用户取消、余额或网络、订单超时、系统异常分别说明并给出重试；已扣款未开通时直达人工客服；权益调整须填原因并留痕。
- **4.3e 退款试算与发票**（建议切片）　与 BILL-04 共用切片
  - 验收：退款先试算再申请、进度可查，超出规则由主管审批；发票可申请、下载、红冲与重开。

人工把关：真机看：手机 375 与桌面 1280 按验收各走一遍（并入闭环收尾走查）

预计：约 12–17 轮（按编程助手口径；1.1 结束后按 docs/product/calibration.yaml 的系数折算）

### 0.2-4 LRN-01 证据账本与掌握档派生

`learner` · R1 · 依赖 MAP-01、CONT-01 · 规格：draft

规格种子（来自分期规划切片 0.2c、0.2d；写规格时转成 R 与 AC；与契约、ADR、glossary 冲突时以后者为准）：
- **0.2c 证据账本与掌握档派生**
  - 目标：证据只追加；档位可从证据整体重算。
  - 范围：证据账本：只追加，不允许更新与删除；撤销用“撤回事件”表示；每条带出处、题目可信度、把握度、用时、时间。
  - 范围：掌握档派生：先用一个最简单的 v0 规则（正式规则由 0.4A 探针定），派生结果放单独的表或视图。
  - 范围：一条命令：从证据重算全部档位。
  - 范围：先写测试：删掉派生表 → 重算 → 结果与删之前完全一致。
  - 不改：作答界面（0.3 做）。
  - 验收：删掉派生表后，一条命令从证据重算出同样的档位。
  - 提醒：证据账本是整个产品唯一的写入汇合点：练习、读后即测、回忆评分、模考、主观题批改都往这里写，档位、预测、错题毕业都从这里读（4.2）。
- **0.2d 统一词汇常量**
  - 范围：把六档掌握度、九类知识类型、七类错因、十二类陷阱、证据强弱做成代码常量（编码、名称、一句话说明、排序、颜色令牌的引用）；界面与算法只引用这一份；写一个测试保证常量与 docs/product/glossary.yaml 一致。
  - 不改：其他代码的行为。
  - 验收：界面与算法引用同一份常量。

人工把关：按步骤里的人工动作做（账号、密钥、环境）；规则表逐行核对：业务确认时看决策表与原型说法是否一致（本功能最重要的把关）

预计：约 4–7 轮（按编程助手口径；1.1 结束后按 docs/product/calibration.yaml 的系数折算）

### 0.2-5 CONT-02 种子导入器与主考试、对照考试种子

`content` · R1 · 依赖 EXM-01、MAP-01、CONT-01 · 规格：draft

规格种子（来自分期规划切片 0.2e；写规格时转成 R 与 AC；与契约、ADR、glossary 冲突时以后者为准）：
- **0.2e 种子导入器与两份种子**
  - 目标：一条命令导入种子考试，可重复执行。
  - 范围：种子格式：JSON 或表格；给我一份带填写说明的模板，方便我整理内容。
  - 范围：导入器：校验（缺字段、引用不存在的知识点、重复 ID 都给出明细）；幂等（重复导入不产生重复数据）。
  - 范围：把原型脚本里的演示数据转成种子：主考试（初级会计职称）一份、对照考试（评价规则不同）一份，放 fixtures/exams/（初级会计与六级已有演示数据，由本功能的导入器读取）。
  - 范围：一个最简单的只读知识点列表页，能看到导入结果。
  - 不改：作答与证据。
  - 验收：一条命令导入种子考试；重复导入不产生重复数据；对照考试的评价规则与主考试不同。
  - 提醒：风险“数据模型被一门考试带偏”：0 期就放一门评价规则不同的对照考试作测试夹具（第 11 章）。

## 功能与规格种子

### 0.1-1 PLAT-01 学员端外壳与通用状态组件

`platform` · R1 · 依赖 PLAT-02、METR-01 · 规格：draft

规格种子（来自分期规划切片 0.1c、0.1d；写规格时转成 R 与 AC；与契约、ADR、glossary 冲突时以后者为准）：
- **0.1c 学员端外壳**
  - 目标：手机、平板、桌面三种宽度下，学员端的导航外壳都能用。
  - 范围：设计令牌（颜色、字号、间距、圆角）取自原型的配色与字体，集中在一个文件。
  - 范围：桌面：侧栏；手机：底部五个标签；顶栏。导航项与命名以原型为准，页面先放占位内容。
  - 范围：键盘可操作、焦点可见；浅色与深色都可读。
  - 不改：任何业务数据与接口。
  - 验收：手机、平板、桌面三种宽度下导航都可用。
- **0.1d 通用组件：三态、提议卡与撤销条骨架**
  - 目标：任意页面能一行代码切到加载、空、出错态；提议卡与撤销条有可复用的骨架。
  - 范围：加载、空、出错三个状态组件；出错时说清发生了什么、怎么办。
  - 范围：提议卡骨架：改什么、为什么、代价、不改会怎样；动作是“确认”和“不改”；确认后出现带撤销期的撤销条。先用假数据演示，不接业务。
  - 范围：组件测试。
  - 不改：业务页面。
  - 验收：任意页面能一行代码切到空态和出错态；提议卡与撤销条在演示页可交互。

人工把关：真机看：手机、平板、桌面三种宽度按验收看一遍（并入闭环收尾走查）

预计：约 4–6 轮（按编程助手口径；1.1 结束后按 docs/product/calibration.yaml 的系数折算）

### 0.1-2 PLAT-02 参数注册与运行时访问器

`platform` · R1 · 依赖 无 · 规格：draft

规格种子（来自分期规划切片 0.1e；写规格时转成 R 与 AC；与契约、ADR、glossary 冲突时以后者为准）：
- **0.1e contracts/params.yaml（一向门）**
  - 目标：所有阈值集中成带默认值、带说明的配置；代码里找不到写死的阈值。
  - 范围：统一的读取函数；读不到就报错，不用魔法数字兜底。
  - 范围：持续集成加一条检查：业务代码里出现可疑的数字字面量就报警（0、1 等列白名单）。
  - 范围：写 ADR“参数外置成注册表”（一向门，原型依据 P19-02、P19-05）。
  - 不改：业务逻辑（现在还没有）。
  - 验收：代码里找不到写死的阈值；每个参数都能查到默认值、可调区间与出处。

人工把关：按步骤里的人工动作做（账号、密钥、环境）

预计：约 2–3 轮（按编程助手口径；1.1 结束后按 docs/product/calibration.yaml 的系数折算）

### 0.1-3 METR-01 埋点事件表与有效学习口径

`metrics` · R1 · 依赖 无 · 规格：draft

规格种子（来自分期规划切片 0.1f；写规格时转成 R 与 AC；与契约、ADR、glossary 冲突时以后者为准）：
- **0.1f 埋点事件表与“有效学习”口径**
  - 目标：北极星先有口径，再有看板；任何一次作答都会落一条可统计的事件。
  - 范围：docs/metrics.md：指标字典 v0——北极星的口径、“有效学习”的判定，以及 1 期要看的五个指标（每周有效学习日数、今日清单完成率、巩固段完成率、次日回访率、访谈里“理由可信”的比例）怎么算。
  - 范围：事件表与写入函数：事件名、必填字段、版本号；先定义“作答”“完成今日一项”“打开今日”三类。
  - 范围：单元测试：写入一条模拟作答事件后，能按口径统计出来。
  - 不改：业务页面。
  - 验收：任何一次作答都会落一条可统计的事件（先用测试中的模拟作答证明）。

人工把关：按步骤里的人工动作做（账号、密钥、环境）

预计：约 2–3 轮（按编程助手口径；1.1 结束后按 docs/product/calibration.yaml 的系数折算）

## 闭环级任务（不属于任何功能，Codex 以轻量或探针方式完成）

- **0.1a 仓库、目录约定与项目记忆**：由文档体系承担（ADR-008）。
  - 验收：新开一个 Codex 会话，只读 AGENTS.md 并运行 `python scripts/spec_tool.py status`，就能说清项目在哪一步、下一步做什么、必须遵守哪些规则。
- **0.1b 按 ADR-025 至 ADR-029 接线**：每次推代码自动构建、跑测试、部署到阿里云预发；失败就拦住。
  - 范围：五个应用骨架：apps/learner、apps/org、apps/admin 用 React 与 Vite，apps/api 用 Fastify，apps/worker 用 BullMQ；packages/contract（Orval）与 packages/db（Prisma 7）；Vite 把 /api 转给本机 API。
  - 范围：docker compose 起 PostgreSQL 17（带 zhparser、pg_bigm、pgvector）与 Redis；deploy/ 放 Dockerfile、compose 文件与发布回滚脚本，并写 deploy/README.md 的“构建与部署”一节，记录一次部署大约要多久。
  - 范围：CI 运行 `python scripts/spec_tool.py verify --full`；加版本锁检查与禁用库检查（含 ADR-025 决定 1 列出的版本陷阱）、依赖方向检查（dependency-cruiser），以及“界面不直接调用 fetch，只用 packages/contract 的钩子”的 lint 规则。
  - 范围：把 contracts/schema/*.yaml 转为 contracts/schema/<领域>.prisma，同一次提交里改 spec_tool 的表结构解析与 docs/conventions/data.md 规则 1、2（ADR-026）。
  - 范围：design/tokens.json 经 Terrazzo 生成 CSS 变量；装好 Playwright 后运行 `python scripts/spec_tool.py shots`，补齐学员端 834 截图。
  - 范围：阿里云预发：ECS 上的 docker compose、RDS PostgreSQL 17、ACR；环境变量与密钥只放部署环境，告诉产品负责人在哪个界面填哪些值。
  - 验收：提交后自动跑测试并部署预发；故意提交一个失败测试时流水线变红且不部署；一条命令能回滚到上一版。

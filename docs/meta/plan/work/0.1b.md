# 0.1b 工程接线计划（闭环 0.1 的闭环级任务）

> 执行者：Codex，在分支 `chore/0.1b-wiring` 上完成，经 PR 与 CI 合入主干；不走交接包，不建 work 文件。
> 时机：0.1-S 规格批次合入主干之后、任何功能出包之前。三个功能计划（PLAT-02、METR-01、PLAT-01）引用的路径以本文件第 3 节为准；实际路径如有变化，同一个 PR 里同步修改三份计划。
> 依据：ADR-025、ADR-026、ADR-027 决定 5、ADR-028 决定 1、ADR-029；闭环文件 loops/0.1.md 的“闭环级任务”；phases.yaml 0.1b 的验收句。

## 1 范围

做：工作区与工具链、五个应用骨架、共享包骨架、生成器、本地与 CI 的数据库、统一错误体与角色校验、固定开发者身份、CI 运行 verify、阿里云预发自动部署与一条命令回滚、学员端 834 截图。

不做：任何功能行为。参数覆盖与学员端取值归 PLAT-02；事件写入与指标归 METR-01；外壳导航、状态组件与令牌取值归 PLAT-01。不做正式登录（0 期用固定开发者身份），不做后台界面。

## 2 交付清单（建议按 A→E 分提交）

### A 工作区与工具链
1. 依赖与版本：按 ADR-025 决定 2 锁定精确版本（package.json 与 pnpm-lock.yaml），Node 24、pnpm 11、TypeScript 6 strict。ADR-025 没有逐个列名、但属于登记工具组成部分的包（Prisma 的 PostgreSQL 驱动适配器、Vitest 浏览器模式的 Playwright 驱动、Orval 的 Zod 输出等）在本 PR 中补写一份 ADR，列出包名与理由；允许清单与禁用清单（含 ADR-025 决定 1 的版本陷阱）接入 verify，由 Codex 维护在 scripts/ 下。
2. 根 tsconfig.json 用项目引用，`pnpm typecheck` 覆盖全部包与测试文件（类型断言测试依赖这一点）。
3. ESLint 10 扁平配置与 Prettier。规则：apps/learner、apps/org、apps/admin 禁用全局 fetch 与 ADR-025 禁用的库，只经 packages/contract 的钩子访问接口；颜色与尺寸只用令牌的样式检查（扫描 CSS、className 与 style，生成物除外），对应 docs/conventions/ui.md 规则 1。
4. dependency-cruiser：界面应用只依赖 packages/ui、packages/contract、packages/params；packages/ui 不依赖 params、contract、domains、db、ai；领域包之间只经包入口，方向按 docs/product/domain-map.yaml 单向无环；@exam-prep/params 的主入口不得引入 node 内置模块。
5. Vitest 4：根 vitest.config.ts 以 projects 覆盖 apps/*、packages/*、tests/；纯逻辑用 node 环境；组件测试用浏览器模式（Playwright 驱动），不引入 jsdom。
6. Playwright：根 playwright.config.ts，testDir 为 tests/e2e（spec_tool 只在 tests/、apps/、packages/、evals/ 下扫描测试标题）；项目 chromium、webkit、firefox；webServer 同时起 api 与 learner；截图基线只在固定版本的 Playwright Linux 镜像中生成，镜像装中文字体；package.json 的 `e2e:smoke` 指向 tests/e2e/smoke。
7. 测试结果：Vitest 与 Playwright 的结果合并写入 .test-results/results.json，格式 `{"tests":[{"title":…,"status":"passed"|"failed"|…}]}`（spec_tool 据此推导 AC 状态）。tests/tooling/ 下的 Python 工具测试（标准库 unittest，不另装依赖）也由 verify 运行，结果并入同一文件，标题取测试方法文档字符串首行；scripts/spec_tool.toml 的 [verify] 增加对应命令。PLAT-02-AC7、AC8 与 METR-01-AC10 是这类测试，不并入就推导不出“完成”。

### B 应用与共享包骨架
路径与导出见第 3 节。要点：
1. apps/api：Fastify 5 与 pino；`buildApp(options)` 返回实例，测试用 inject，options 可注入请求身份的来源（测试据此构造 learner、guest 以外的角色，METR-01-AC3 要用）；在 /api 前缀下注册 platform 与 metrics 两个领域包导出的路由插件（插件此时为空）。
2. apps/worker：BullMQ 连接 Redis，暂无任务，可启动、可健康检查。
3. apps/learner：React 19.2、Vite、React Router 7 声明式路由、TanStack Query 5、Tailwind 4、i18next；Vite 把 /api 转给本机 API；构建模式即环境名（`vite build --mode staging`）；首页暂时只显示“学员端”。
4. apps/org、apps/admin：最小 Vite 应用，只显示“尚未开放”。
5. 环境名 EXAM_PREP_ENV：development、test、staging、production；未设置按 development，其他值拒绝启动。
6. 固定开发者身份（0 期不做正式登录）：每个请求的 RequestContext 取 EXAM_PREP_DEV_LEARNER_ID、EXAM_PREP_DEV_TENANT_ID、EXAM_PREP_DEV_ROLE（learner 或 guest，默认 learner）、EXAM_PREP_DEV_TIMEZONE（默认 Asia/Shanghai）；guest 由 role 推出。EXAM_PREP_ENV 为 production 时拒绝启动（正式登录接入前生产环境不可用）。浏览器不能通过任何请求字段切换身份。
7. 统一错误体 {code, message_key, details}（docs/conventions/api.md 规则 3）：请求体解析失败、未知路由、请求体过大、媒体类型不支持、未预期异常分别为 COMMON_BAD_REQUEST、COMMON_NOT_FOUND、COMMON_PAYLOAD_TOO_LARGE、COMMON_UNSUPPORTED_MEDIA_TYPE、COMMON_INTERNAL；未预期异常不回显细节，日志带请求 ID；领域代码抛出 ApiError 时按其 code 输出。
8. 角色校验：路由声明所用动作（contracts/permissions.yaml 的 id），统一钩子比对 RequestContext.role 与动作允许的角色，不允许时返回 COMMON_FORBIDDEN；openapi 中标 x-public 的接口不要求登录（0 期每个请求都带固定身份，此标注在 1.6 接入登录后生效）。

### C 生成器（spec_tool gen；产物头部带 GENERATED，gen --check 检查漂移，手改被检出）
1. 参数：gen 的参数产物改为 packages/params/registry.generated.ts，只含登记数据与类型（ParamName、ParamValue、每项的 integer 标记：YAML 默认值为整数即为真）。packages/params/index.ts 变为手写文件，暂时保留现有 `param()`、`setParamSource()` 的行为，由 PLAT-02 重写。
2. 学员端页面清单：design/screens/learner/*.yaml → apps/learner/src/generated/pages.ts（页面 ID、title、mode、各视图的 id 与 mode）。
3. 错误码：contracts/errors.yaml → packages/contract/src/generated/error-codes.ts（code、HTTP 状态、文案键）。
4. 权限：contracts/permissions.yaml → packages/contract/src/generated/permissions.ts（动作 → 允许的角色）。
5. 事件与指标登记：contracts/events.yaml、contracts/metrics.yaml → packages/domains/metrics/src/generated/events.ts、metrics.ts。
6. 接口：contracts/openapi.yaml → packages/contract/src/generated/（Orval：类型、Zod 结构、TanStack Query 钩子、MSW 模拟；`pnpm contract:gen`，verify 检查漂移）。先用一个最小样例确认 Orval 输出的 Zod 4 写法（ADR-025 后果）。
7. 令牌：design/tokens.json 与 tokens.resolver.json → packages/ui/src/generated/tokens.css。基础值放在外壳根元素上，每个修饰器按根元素的 data-* 属性覆盖（data-brand、data-vision、data-text，以及 PLAT-01 将新增的 data-scheme）；新增修饰器或上下文不需要改生成器。未解析的别名、重名即生成失败。brand 的 org 上下文依赖机构配置，0 期构建时跳过。用 Terrazzo，或 ADR-025 写明的退路（spec_tool gen 两层文件）。packages/ui/src/theme.css 把 Tailwind 4 的主题映射到这些变量，清空默认调色板与默认间距，界面只能用登记的令牌类。
8. 表结构：contracts/schema/*.yaml 转为 contracts/schema/<领域>.prisma 多文件 schema，同一次提交改 spec_tool 的表结构解析（E-OWN-01、E-DC-01）与 docs/conventions/data.md 规则 1、2（ADR-026 决定 4）；首个迁移按转换后的全部表生成，含 METR-01 登记的 analytics_events。

### D 本地运行与数据库
1. deploy/compose.yaml：PostgreSQL 17（自制镜像 deploy/postgres/Dockerfile，带 zhparser、pg_bigm、pgvector）与 Redis 7（开 AOF）。
2. packages/db：Prisma 7 客户端的唯一构造处；`withContext(ctx, fn)` 为第一道租户防线（ADR-028 决定 1）；测试辅助为每个测试文件提供隔离的连接与清表。
3. `pnpm db:migrate`、`pnpm db:seed`：种子写入平台默认租户与固定开发者账号（学员、游客各一），ID 与 .env.example 一致。
4. .env.example 列出全部变量名与说明，不含取值；.env 不进仓库。

### E CI、预发与回滚
1. .github/workflows/ci.yml：Node 24、pnpm 11、Python 3.12；pnpm install --frozen-lockfile；PostgreSQL 17 与 Redis 作为服务容器；运行 `python3 scripts/spec_tool.py verify --full`；主干合并后构建 api 与 worker 镜像推送 ACR，构建 learner、org、admin 静态文件，部署预发；verify 失败不构建、不部署。
2. deploy/：Dockerfile（api 与 worker 同镜像不同入口）、compose.staging.yaml（Caddy、api、worker、Redis）、Caddyfile（/api 转 api；其余为学员端静态文件，前端路由回退到 index.html，/api 下的未知地址仍返回 JSON 404）、release.sh（备份 → 迁移 → 替换容器 → 记录版本）、rollback.sh（一条命令回到上一版镜像）、README.md 的“构建与部署”一节（记下一次部署的实测耗时，0 期观测指标要用）。
3. 预发的环境变量与密钥只放 GitHub Secrets 与 ECS 上的 .env。
4. 装好 Playwright 后运行 `python scripts/spec_tool.py shots`，补齐学员端 834 截图（ADR-029 后果）。

## 4 产品负责人要做的
1. GitHub：仓库开启 Actions；按 Codex 给的清单在 Secrets 填写镜像仓库与预发服务器的登录信息。
2. 阿里云：开通 ECS（预发一台）、RDS PostgreSQL 17、容器镜像服务 ACR；按 Codex 的清单在 ECS 的 .env 填写数据库与 Redis 连接、EXAM_PREP_ENV=staging 与固定开发者身份。
3. 决定预发怎么访问：域名 ICP 备案完成前，境内服务器不能用域名对外提供网站服务。可选：先用 ECS 公网 IP 访问预发（只给自己用）；或先把预发放在不需要备案的地域；或等备案完成。默认建议第一种。
4. 用手机与电脑各打开一次预发地址，回复“能打开”。

## 5 验收（0.1b 完成判据）
1. 本地 `pnpm install` 后，`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm e2e:smoke` 全部通过；`python3 scripts/spec_tool.py verify --full` 通过。
2. 推一个提交到主干：CI 跑完 verify 后自动部署预发，手机与电脑都能打开学员端骨架页。
3. 提交一个故意失败的测试（PR）：CI 变红，不构建、不部署。
4. `deploy/rollback.sh` 一条命令回到上一版，记录耗时。
5. `gen --check` 覆盖第 2 节 C 的全部产物；手改任一产物会被检出。
6. 依赖方向、版本锁、禁用库、界面禁用 fetch、样式字面量五项检查各用一个反例证明能拦住（反例不提交）。
7. 学员端 375、834、1280 三种宽度的原型截图齐全。
8. 新开一个 Codex 会话，只读 AGENTS.md 并运行 `python scripts/spec_tool.py status`，能说清位置、下一步与必须遵守的规则（0.1a 的验收，顺带核对）。
9. tests/tooling/ 的工具测试计入 .test-results/results.json。

定位判据（README 第 2 节按 steps.md 顺序判断 0.1-T 0.1b 是否完成时用）：主干上有 pnpm-lock.yaml、apps/api/src/app.ts 与 deploy/rollback.sh。

## 6 风险与应对
1. 预算 2–4 轮偏紧。先保证第 5 节 1–4（CI 与部署）；截图与样式检查在 PLAT-01 出包前完成即可。
2. Prisma 7 与 Orval 的 Zod 4 写法要先用最小样例确认；不通过时停下，按 ADR-025“何时重新考虑”处理。
3. 组件测试的浏览器模式需要的包不在 ADR-025 逐个列出，按 A1 补写 ADR 后再装。
4. 截图基线依赖字体与浏览器版本，只在固定镜像中生成与比对；Windows 与真机走查不更新基线。
5. 0.1b 改动面大，评审时按 A–E 分提交看。

- 黄金路径 1–6 全绿

- 首次使用／时间与资料：薄

风险巡检：
- 档位与预测不被信任：访谈里说“理由看不懂”、用户频繁用自评覆盖系统判定 → 调规则参数、加强解释，必要时减少数字露出。
- 闭环超预算：看calibration.yaml，按 3.3 的规则熔断与校准。
- AI 改坏旧功能：黄金路径变红 → 回滚到上一个全绿提交，缩小切片重做。
- 一个人的带宽：同时想做开发、内容和运营 → 砍范围，而不是延期。

滚动细化：Codex 汇总本期 docs/product/calibration.yaml 算出系数，重估下一期预算，复核下一期各闭环的功能切分与规格种子，起草期复盘与下一期调整，交你确认。

## 本期的关键判断（分期规划原文）

- 今日清单是 1 期的脊柱。1.2 先把它搭起来，只亮推进段；之后每个闭环都像插件一样插进某一段：错题和复习插进巩固段，计划给整条清单分配时间。从 1.2 起，用户每天就有一个真实入口，每多关上一个闭环，清单就多一种任务。
- 为什么是这个顺序。1.1 先做“练习产生证据”，因为证据是整个产品唯一的写入源头，后面的每个闭环都读它；它也是对 0 期证据规则的第一次真实检验。1.2 紧跟着做今日，因为它此时只需要一种任务来源（练习），用最薄的生成器就能跑通。1.3 错题放在记忆之前，因为它只依赖练习、规则清楚，并且由它来定义“到期队列”接口。1.4 记忆队列作为到期队列的第二个实现接入，接口被两个实现检验过，6 期背诵接入时几乎不用改。1.5 计划放在最后，因为排程要分配的东西（新学、练习、错题、复习）此时才都存在；任务来源不全时做排程，只能对着假数据调参数。1.6 账号放在邀请外人之前：前五个闭环用开发者账号就够了，而登录方式多是双向门，晚定不贵。
- 到期队列先有接口，再有两个实现。原型说“复习与卡片”是唯一到期队列的家（S15），到期的错题也在复习会话里切换出现（S15-18）。所以 1.3 不要把回炉写死在错题模块里，而是先定义“列出今天到期的项”“完成一项并写入证据”这两个接口。

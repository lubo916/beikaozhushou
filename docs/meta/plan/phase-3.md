> 受众环 ring-1+：延续 2 期的受邀用户；验证要跨越至少一个真实考期，因此本期的“验证”会持续到 4、5 期开发期间。 · 预算 155–215 轮 · 闭环 6 个 · 执行顺序 3.1 → 3.2 → 3.3 → 3.4 → 3.5 → 3.6

## 并行事项、门槛与决策点（按出现位置）

- **并行事项：整理考情数据**
  - 你：为种子考试整理考情数据：各知识点的分值、考察概率与出处（往年真题统计）。拿不到的就留空，3.2d 会按“无考情降级”处理。
  - Codex：给出考情数据的种子模板，并检查你整理的数据格式。
  - 完成：考情数据进了种子，或明确标注“暂无”。
- **决策点：选路线：继续默认 A，还是 B（机构试点先行）**
  - 你：如果已有机构愿意付费试点、班上学员考的正是你的种子考试，可以选 B；否则继续 A。
  - Codex：对比 A 与 B 的代价。
  - 完成：写成 ADR（Codex 在主干用 new adr 分配编号）。

## 期末（P3-出）

出口标准：
- 至少一批用户完成一次模考并采纳补强提议
- 周复盘连续运行四周以上
- 考后成绩回填流程跑通（先用模拟数据演练，真实验证随考期滚动）

观测指标：
- 模考后七天内补强提议的采纳率、周复盘完成率、“只改一件事”写回率、考后回填后预测区间的命中情况

旅程检查：本期结束时用户能走到哪：
- 一天／到期复习：厚
- 一天／练习：厚
- 一个考期／阶段测评：全
- 一个考期／每周调整：全
- 一个考期／冲刺：全
- 一个考期／考后与下一站：全

风险巡检：
- 验证要等真实考期：3 期功能做完了却没有成绩回填 → 用模拟数据演练流程，真实验证随考期滚动。

滚动细化：Codex 汇总本期 docs/product/calibration.yaml 算出系数，重估下一期预算，复核下一期各闭环的功能切分与规格种子，起草期复盘与下一期调整，交你确认。

## 本期的关键判断（分期规划原文）

- 验证周期不等于开发周期。3 期的功能几周就能做完，但“预测准不准”“冲刺有没有用”要等用户真的考完才知道。所以 3 期的出口只要求流程跑通（可以用模拟数据演练成绩回填），真实验证随考期滚动，在 4、5 期开发期间持续收集。这也是 1 期就要招募考期合适的用户的原因。
- 预测的“诚实”是产品承诺。原型对预测有一整套约束：只给区间不给单点，标明证据量，没有考情时降级并标注，体检不通过时锁定，往期预测公开校准。3.2 要把前三条做全；锁定在 5.5，校准公示需要足够的回填数据，放到 8 期以后。
- 模考复用练习引擎。整卷会话是在 1.1 的作答流程上加“交卷后统一揭晓”（2.2 的测评态已经做过一次），再加严格计时与过程记录；测评报告复用统一的错因与陷阱分类。

# 地基文档目录

> 这里放“跨页面、改起来贵”的约定，只写现状，不写历史。每份 300 行以内。
> 只有地基任务（F 开头）和整合任务（I、B21）可以改这里；其他任务需要改，写进交接单。
> 初稿由 V4 工具包提供，任务 F01 负责对照原型和仓库已有资料核对、改正。

| 文件 | 管什么 | 谁要读 |
|---|---|---|
| decision-sheet.md | 开工决策单：开工前要用户定的 15 件事与默认值 | Codex（F00 后念给用户）、F01 |
| tech.md | 技术栈、锁定版本、目录结构、网页沙箱与本地环境的注意事项 | 工程类任务 |
| vocabulary.md | 统一词汇：掌握六档、知识类型、错因、陷阱、页面七态、三个数等 | 所有任务 |
| pages.md | 70 页清单：路由、分组、模式、视图、功能点数量 | 页面任务 |
| ui-rules.md | 设计令牌、断点、外壳、七态、文案、组件、样板页 | 页面任务 |
| api-rules.md | 接口约定、页面怎么拿数据、假数据与真假切换 | 页面任务、后端任务 |
| data-model.md | 核心对象与关系、11 个一向门决定、硬规则 | 后端任务、规则卡 |
| metrics.md | 统计口径：三个数、正确率、有效学习时长等 | 规则卡、后端、报告类页面 |
| golden-paths.md | 6 条黄金路径：冒烟测试与走查的依据 | 测试任务、整合任务 |

| rule-cards/ | 规则卡：原型上看不见的业务规则，例子即规格 | 对应的后端任务 |

权威顺序：红线（AGENTS.md）＞ docs/decisions/ 里你拍板的决定 ＞ 本目录（含勘误表）＞ 原型。

单一来源：V3 已有的 docs/product/glossary.yaml（术语）、contracts/params.yaml（参数）如果存在，就是词汇常量与参数访问器的生成来源；vocabulary.md 只做人读的摘要，二者冲突以 yaml 为准并记进勘误表。

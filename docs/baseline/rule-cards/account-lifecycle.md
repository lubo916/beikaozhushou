# 规则卡：账号生命周期

- 状态：草稿（R08 第 1 轮；你拍板的 R08-Q1～Q6 已写入，见决定卡 D-2026-10-21-R08-r1；R08-Q7、Q8 待拍板，先按临时默认写；整卡等你说“规则确认 R08”后定稿）
- 用在：S01-01、02、03、04、05、07、08、13、14、15、16、18、19、20、21；S32-01、09、10、18、22、23、29、30；S33-01、14、16。未成年人模式的开关另由 S21（视频分析）、S30（社交）、会员付费与消息推送读取；P18 只调本卡的参数
- 由谁执行：B13 实现 account 领域：年龄段判定、未成年人开关、游客合并、登录结果、会话下线、注销状态都写成纯函数，放 packages/domains/account/core/；L02 接入真实短信与微信时沿用 R19–R21。其他领域只读本卡给出的结果（年龄段、开关、不推送时段），不自己判断年龄

## 目的

管住一个账号从“先体验”到“注销删除”的全过程：先确认年龄段，未成年人受保护；不注册也能用，登录后游客期间的记录一条不丢地带进账号；登录要安全，但不刁难本人；注销有冷静期，删得干净，也说得清楚删了什么、留了什么。

## 什么时候用

- 首屏选年龄段、点“先体验，不注册”时（R1–R4、R9）。
- 每次取当前用户的上下文时：算年龄段（是否已满 18 岁）、未成年人模式的各项开关、实际不推送的时段（R5–R8）。
- 游客或老用户登录时：协议同意、验证码、受限、冷静期、设备上限、登录后去哪（R18–R24、R28）；游客还要合并（R11–R17）。
- 改密码、重设密码、换绑手机号、在设备列表里让某台下线、异地登录点“不是我”、平台强制下线时（R24–R27）。
- 申请注销、冷静期内登录、撤销注销、期满删除时（R29–R35）。
- 每天清理一次长期不用的游客（R10）。

## 输入

- 账号（users 表，packages/db 的 account.prisma）：kind（guest 游客、registered 正式）、age_band（unconfirmed 未确认、under_min 未到最低年龄、minor 14 至 17 岁、adult 成年）、minor_mode、status（active 正常、restricted 受限、cooling_off 冷静期、deleted 已删除）、phone、merged_into、merged_at、created_at。
- 本卡需要新增的账号数据（B13 补，数据结构冻结前用 db push）：birth_month 出生年月（只在选“14 至 17 岁”时填）、last_active_at 最后一次使用时刻（清除游客用）、微信 UnionID 与 Apple 账号的绑定、注销记录（申请时刻、期满时刻、撤销时刻）、受限记录（原因、到期时刻）、密码（只存不可逆摘要）。
- 会话与设备：设备名、客户端、登录方式、地点（到城市）、登录时刻、最后活动时刻、下线时刻与原因；本人确认过的常用地点。
- 只追加的记录：协议同意（哪份文件、版本、时刻、设备）、账号活动（登录、改密、换绑、被下线、注销申请与撤销）、登录失败。
- 游客和账号各自的学习数据（合并用）：目标（考试、主次、目标分、目标日）、计划、时间预算与偏好、只追加的学习记录（作答、证据、复习记录、重排记录）、笔记、标注、卡片、错题、资料。
- 机构关系（注销用）：入班关系、学员给机构的逐项授权。
- 当前档位的同时在线设备上限（会员权益，R10 定）；《用户协议》《隐私政策》的现行版本。
- 当前时刻；用户时区与日界线（默认北京时间、凌晨 4 点切日），“哪一天”一律用 packages/shared/src/today 的 today 函数算。
- 参数：见“参数”一节。

## 输出

- 年龄段：age_band、minor_mode、birth_month、满 18 岁的日子；能不能用（service）；未成年人的三个开关（社交、付费、视频分析）与不推送时段；要不要补选或再确认年龄段。
- 游客：游客身份；什么时候清除。
- 合并：模式（原地转正、并入已有账号、先不合并、已合并过）、并入哪个账号、目标与计划以谁为准、追加了多少条记录、要重算哪些数、年龄段要不要再确认；给页面的摘要数字。
- 登录：成功、要先勾协议、要重新同意新版本、设备已达上限（附在线设备列表）、受限（原因、到什么时候）、冷静期（还剩几天、删除范围）、验证码错误或过期、发送太频繁；成功后去哪一页、回到哪个位置。
- 下线：哪些会话结束、各自的原因代码（S01“账号异常”屏按原因显示说明）。
- 注销：状态变化、期满时刻、还剩几天；期满时的删除清单（删除、作废、按法定保留、去身份保留、机构侧怎么处理）。
- 页面上：S01 的首次进入、回访登录、账号异常三种视图；S32“账号与设备”标签的登录设备、异地登录确认、登录记录、未成年人模式、注销账号；S33“账号”标签的密码、手机号、第三方绑定。页面只显示接口给的结果（红线 5）；文案里的规则数字全部用参数插值（红线 2）。

## 规则（大白话，编号）

### 一、年龄段与未成年人

R1 首屏必须先选年龄段，不设默认。三个选项是“18 岁及以上”“14 至 17 岁”“14 岁以下”，其中 14、18 来自参数 account.age.min_service_age、account.age.adult_age（文案插值）。没选之前“先体验，不注册”不能点。任何时候年龄段还是“未确认”的人，一律按未成年人处理（INV-06）。

R2 选“18 岁及以上”记为 adult；选“14 至 17 岁”记为 minor，并且要填出生年月，只填年和月（R08-Q1＝A）；选“14 岁以下”记为 under_min，按 R4 处理。

R3 出生年月必须和所选年龄段对得上：按 R6 的算法，到“今天”已满 14 岁、未满 18 岁才收下。对不上就不保存，提示“出生年月和所选年龄段对不上，请重新选择”。

R4 未到最低年龄不提供服务：不建游客、不建账号、服务端不留任何记录，也就不保存任何学习数据（INV-06），页面只显示“暂不提供服务”。已经登录的账号被确认为未满 14 岁时（R17 的再次确认里选了“14 岁以下”，或人工核验认定）：先提供“导出全部数据”，本人再确认一次后，立即让所有设备下线、停止服务，按 R34 的范围当场删除，不走冷静期（待拍板：R08-Q7，临时按 A 写）。

R5 未成年人模式由年龄段推出来：年龄段是 minor 或 unconfirmed 就开，adult 就关。没有任何开关能直接改它，本人在设置里也关不掉（INV-06）。其他领域和页面只读本领域给出的结果，不自己判断年龄。

R6 满 18 岁自动转成年（R08-Q1＝A）。只知道出生年月、不知道哪一天，所以按偏保守的算法：“满 N 岁的日子”＝出生年加 N 年、出生月的下一个月的 1 日，和 today 函数算出的“今天”比（凌晨 4 点切日）。到了满 18 岁的日子，年龄段自动改为 adult、未成年人模式关闭，记一条账号活动，下次进入时提示一次。

R7 年龄段确认之后，本人不能自己改（设置里没有入口）：不能把未成年改成成年，也不能改已填的出生年月。确实选错了，走人工核验（后台操作按 ADR-020 重验身份、留痕、可回滚）。年龄段唯一的自动变化是 R6。

R8 未成年人模式下（含未确认）：不开放社交（S30 只留自习室与番茄钟）、不开放付费、不开放视频分析（S21），每天 22:00 至次日 6:00 不推送（参数 account.minor.quiet_window）。实际不推送的时段＝本人设置的免打扰时段（engagement.quiet_hours）和这一段的并集：本人只能加长，不能缩短。安全提醒（异地登录、多次登录失败等）对成年人不受免打扰限制、立即推送；对未成年人，22:00 至 6:00 这一段也不推，到 6:00 再推，账号活动照常立即记录。

### 二、游客与合并

R9 游客和正式用户在同一张表，用 kind 区分（ADR-012）。首屏选了年龄段（成年或 14 至 17 岁）后点“先体验，不注册”，就建一个游客身份和这台设备上的匿名会话；游客的目标、摸底、学习记录从一开始就记在这个身份下。游客能做哪些事，以 contracts/permissions.yaml 里 guest 角色为准；要保存结果（选方案、生成计划）、付费、加入机构时才要求登录。

R10 游客最后一次使用后满 account.guest.retention_days（30）天（精确到秒）还没登录，就删除这个游客身份和它的全部数据，不可恢复（R08-Q6＝A）。页面提示“{{days}} 天不用会清除，登录即可保存”。已并入账号的游客不按这条清除，跟着账号走（R12）。

R11 游客登录时（四种方式都一样），按这次的登录凭据（手机号、微信 UnionID、Apple 账号）找已有账号：

- 找不到，或找到的账号已删除：游客原地转正，kind 改为 registered，id 不变，绑上凭据，什么数据都不用搬（data-model 一向门 6）。
- 找到一个正常的账号：把游客并入这个账号（R12–R17），游客记下 merged_into、merged_at，此后不能再用。
- 找到的账号在冷静期或受限中：先不合并，游客原样保留；登录照常进入冷静期屏（R31）或受限屏（R22）。撤销注销或受限解除后，下一次登录再合并。

R12 合并只追加、不改原记录（红线 6）：作答、证据、复习记录、重排记录这些只追加的记录，复制一份追加到账号下，保留原来的发生时间，标上“来自游客合并”和游客 id，记录之间的引用关系照原样对应。游客那边的原始记录不改不删，不再显示、不再参与计算，只作凭证，跟着并入的账号一起删除（R34）。掌握档、记忆状态、预测、完成度、健康度这些算出来的数，按账号的全部记录重算，不直接搬（ADR-012：合并不丢证据）。

R13 目标冲突（R08-Q5＝A）：

- 账号一个目标都没有：游客的目标照搬，游客的主目标就是主目标。
- 账号已有别的考试的主目标：游客的目标作为次目标加进来，主目标不变；进入时提示一次“已把 X 加为第二个目标，可在备考目标里切换”。
- 两边是同一个考试：以账号的目标为准（目标分、目标日都不变），游客的这个目标不保留；游客在这个考试上的作答、证据照样按 R12 追加。
- 计划跟着目标走：新加进来的目标带上游客的计划；同一个考试以账号的计划为准，游客的计划丢弃。起点报告同理，报告本身怎么生成见 R05。

R14 其他冲突一律以账号已有的为准，账号没有的才用游客的：时间预算、学习节奏、提醒设置、外观等偏好逐项比较。同一个对象两边都有（同一知识点的回忆卡、同一道题的错题）：保留账号那份，把游客那份上的复习记录、作答追加上去，状态按发生时间从全部记录重算（重算规则见 R02、R03）。笔记、标注、卡片、资料这类各自独立的对象，全部加进账号。

R15 同一个游客只合并一次。重复请求（比如网络重试）结果和第一次一样，不会多出重复记录；已经并入某个账号的游客，不能再并入别的账号。

R16 合并后给一份摘要（加了几个目标、追加了多少条作答、哪些以账号为准），进入今日时提示一次；数字由接口给，页面不自己数。

R17 合并时年龄段不一致（R08-Q2＝C，按 INV-06 落地）：

- 账号年龄段还是未确认：用游客选的（连同出生年月）。
- 两边一样：不变。
- 游客选的比账号更严（账号成年，游客选了 14 至 17 岁）：登录后请本人再确认一次，确认之前按更严的算（未成年人模式）。确认“18 岁及以上”就保持成年；确认“14 至 17 岁”就改为未成年并记出生年月；确认“14 岁以下”按 R4。
- 账号比游客更严（账号未成年、游客选了成年），或账号里已有出生年月：以账号为准，不再询问。否则就等于本人自己关掉了未成年人模式（R7）。

### 三、登录、会话与设备

R18 登录或注册前，本人必须勾选同意《用户协议》《隐私政策》，不默认勾选，没勾不能登录。同意记录按文件分别记（文件、版本、时刻、设备），只追加；已经同意过现行版本的不重复记。两份文件任一出了新版本，下次登录或进入时要重新同意；不同意的，只能导出数据或申请注销。

R19 四种登录方式：手机验证码（主方式，新号码验证通过即完成注册）、手机号加密码、微信、Apple。微信、Apple 授权失败时回落到手机号登录。从回访登录页直接用新号码注册的人没选过年龄段：账号记为“未确认”，进入后先补选（R1、R2），补选之前按未成年人处理。

R20 验证码：6 位数字，发出后 account.otp.ttl_minutes（5）分钟内有效；同一个码输错 account.otp.max_attempts（5）次就作废，要重新获取；重新获取至少隔 account.otp.resend_seconds（60）秒；同一号码每天（按 today 函数）最多发 account.otp.daily_max_per_phone（10）次；发送前先过人机验证（ADR-027）。

R21 只用微信登录、没绑手机号的账号（OQ-007，2026-10-18 已定）可以正常学习；付费、注销、换绑、管理设备之前，必须先绑手机号。只用 Apple 登录、没绑手机号的账号同样处理，只有注销例外：用 Apple 重新授权验证本人即可申请（待拍板：R08-Q8，临时按 B 写）。这种情况叫“待绑手机号”，不叫“受限”，免得和 R22 的账号受限混淆。

R22 密码输错与账号受限：

- 60 分钟内（account.login.fail_window_minutes，含正好 60 分钟前那次）密码输错达到 account.login.fail_notify_count（5）次：通知本人，建议改密码（安全提醒，不能关闭）。
- 达到 account.login.fail_lock_count（10）次：账号受限 account.login.lock_hours（24）小时，到点自动解除。登录成功后输错次数清零。
- 平台封禁由后台另定原因和期限。
- 受限期间登录只进受限屏：说明原因、到什么时候、申诉入口；导出全部数据不受影响；其余功能不可用；游客合并暂缓（R11）。

R23 同时在线的设备数，上限取当前档位的权益（R10 定），档位没给就用 account.session.max_devices（3）。已满时再登录：列出在线设备，本人选一台让它下线后继续登录；取消就不登录。游客会话不算在内。

R24 忘记密码：在登录页用手机验证码重设，不用先进设置。号码没注册时，提示和已注册时一模一样（“如果这个号码已注册，验证码已发出”），只是实际不发短信。重设成功后，所有已登录的设备下线。

R25 改密码要先验证旧密码；新密码至少 account.password.min_length（8）位，字母和数字都要有。换绑手机号要两步验证（先验证本人，再验证新号码）；新号码已被别的账号占用（含冷静期中的账号）不能换绑，已删除账号释放的号码可以用。改密码、换绑成功后，除当前设备外全部下线。

R26 下线原因分三种（S01-21）：其他设备让你下线（新设备登录时选了它，或本人在设备列表里让它下线）；改了密码或换绑了手机号（含 R24 重设密码和 R27 的“不是我”）；平台为保护账号让所有设备下线（这不是封禁，可以直接重新登录）。没提交的作答与笔记暂存在本机，同一账号重新登录后恢复；换别的账号登录不恢复。

R27 在不常用的地点登录，通知本人确认（安全提醒，不受频控、不能关闭）。点“是我本人”：记为常用地点；点“不是我”：立即改密码，改完后其他设备全部下线。登录、改密、换绑、被下线、注销申请与撤销都记进账号活动记录（只追加，S32-18、S32-29）。

R28 登录后去哪：有目标的进今日（S06），并回到上次学习的位置；上次的位置已经不存在（比如内容删了）就只进今日；还没有目标的进备考目标（S02）。

### 四、注销与冷静期

R29 申请注销要在登录状态下、账号正常时提出，并重新验证本人（验证码发到绑定的手机；待绑手机号的按 R21；验证服务不可用时一律拒绝、不跳过，ADR-020）。申请前页面说明删除范围与法定保存，并可以先完整导出。

R30 申请后账号进入冷静期，记下申请时刻；期满时刻＝申请时刻＋account.deregister.cooling_days（15）×24 小时，精确到秒。所有设备立即下线，学习提醒停发。

R31 冷静期内可以登录，但只进冷静期屏：说明还剩几天和将删除的范围，可以“撤销注销”“继续注销”或导出数据；登录本身不撤销（S01-20）。“还剩 N 天”＝期满时刻所在的那一天减去今天（两边都用 today 函数），最小为 0；为 0 时提示“今天 HH:MM 后删除”。

R32 冷静期内本人点“撤销注销”：账号回到正常，什么都没删，一切照旧。撤销后还可以再申请，冷静期从新的申请时刻重新算。“继续注销”只是退出，冷静期照常走。

R33 到期满时刻才删除，不提前。删除后账号状态为已删除，不能再登录；手机号释放，以后用它登录就是一个全新的空账号，和旧账号没有任何关系。

R34 删除范围（R08-Q4＝A；法定范围待法务确认，OQ-014）：

- 删除：目标、计划、时间预算、资料、笔记、标注、卡片、作答记录、证据、掌握档、复习记录、错题、预测、导师对话与导师记忆、情绪打卡、危机记录、设置与偏好、登录设备与登录记录、权限使用记录、通知、手机号、出生年月、微信与 Apple 绑定、回收站里的全部内容；并入过这个账号的游客原始记录一并删除。
- 作废：分享链接。别人已经导入到自己账号里的副本归别人，不删。
- 按法定要求保留：订单与发票（保存年限交法务与 R10）。
- 去掉身份后保留：审计日志、协议同意记录（作凭证）；平台统计用的事件。已经算好的统计数字不回头改。

R35 机构那边（R08-Q3＝B）：机构任务数据（作业提交、班级考试成绩、考勤）去掉身份，只在班级统计里留匿名的数，显示为“已注销学员”；学员授权给机构的个人学习数据、推断数据的副本，按撤回授权处理，在 compliance.revoke.purge_days（30）天内删除（INV-07）。
